# TH1520 硬件接口

本驱动支持 TH1520 上 ASIC ID 为 `0x80018000`、build ID 为 `0x1f88` 的
VC8000D。ASIC ID 位于解码核寄存器 0，build ID 位于寄存器 309。
`probe` 检查两个标识，其他产品或 build 返回 `-ENODEV`。

本文记录本项目的硬件观察与当前实现约束，源码中的编号和位域适用于上述
硬件。具体覆盖程度见 [验证记录](validation.md)。

## 平台资源

| 资源 | 当前约定 |
| --- | --- |
| 设备树 compatible | `xuantie,th1520-vc8000d`；另接受 `thead,light-vc8000d` |
| 实测设备树资源 | 子系统基址 `0xffecc00000`，大小 `0x800000` |
| 解码核偏移 | 子系统基址加 `0x1000` |
| 解码核窗口 | 1023 个 32 bit 寄存器 |
| 时钟名称 | `cclk`、`aclk`、`pclk`，按名称从设备树获取 |
| 中断 | 从 platform 资源索引 0 获取，另接受可选索引 1 |
| DMA | 32 bit，原生帧与辅助表使用 coherent DMA 分配 |
| 电源管理 | runtime PM 配合批量时钟启停 |

硬件验证使用系统现有的 `xuantie,th1520-vc8000d` 节点。设备树的 `reg`
描述整个 VPU 子系统，驱动在内部选择解码核窗口。时钟、IRQ 和电源域沿用
板级设备树提供的资源；本仓库通过 `tools/board-load.sh` 在当前启动期间
切换解码驱动，编码器由独立设备管理。

子系统 MMU 位于偏移 `0x3000`，标识和控制寄存器分别为该块的第 6、226 个
32 bit 字。驱动使用物理 DMA 地址，在 `probe` 中读取 MMU 状态，必要时
清除控制寄存器的使能位。硬件验证期间 MMU 为关闭状态。主动 MMU 翻译与
大于 4 GiB 的 DMA 地址尚未验证。

## 寄存器与作业调度

寄存器 `N` 的字节偏移为 `4 * N`。两个 codec 使用同一个 512 字影子数组，
默认提交寄存器 3 至 511，再提交寄存器 2，最后提交寄存器 1。寄存器 1
的启动位触发解码；只读寄存器 0 保持原值。完整提交用于清除前一 context
或 codec 的配置。

`flush_all=0` 是诊断用稀疏提交选项，默认值为 1，硬件验证采用默认设置。
V4L2 M2M 在一个解码核上串行调度作业。IRQ 与软件 watchdog 在同一自旋锁
保护下取得活动作业，以保证每个请求只完成一次。

| 寄存器 | 当前用途 |
| --- | --- |
| 1 | 启动、中止、IRQ 状态及屏蔽 |
| 2 | 数据交换与寄存器时钟控制；H.264 为 `0x3480`，HEVC 为 `0x400` |
| 3 的 31:27 | 解码模式：H.264 使用 0 或 15，HEVC 使用 12 |
| 6 | 完整 32 bit 码流长度 |
| 13 的 31、30:24 | Annex-B 起始码解析与初始 QP |
| 38 | 长期参考帧位图，两个 codec 共用 |
| 58、60 | AXI 总线参数与事务 ID |
| 258、259 | 输入缓冲容量与起始偏移 |
| 265 | 两个 10 bit 字段设置为 64，主使能位保持关闭；字段细义待验证 |
| 318、319 | 硬件超时计数器，启用覆盖并设置 5242880 个周期 |
| 320 至 511 | 后处理器配置区域 |

IRQ 中的就绪状态位为 bit 12。总线错误、输入耗尽、码流错误和硬件超时
分别通过 bit 13、14、16、18 报告；同一次 IRQ 含有错误状态时，请求返回
`VB2_BUF_STATE_ERROR`。软件 watchdog 为 2 秒。中止操作屏蔽中断、请求
停止、等待启动位清除，再清空配置。故障注入专项的执行状态见验证记录。

## 原生参考帧与显示输出

每个 CAPTURE 缓冲关联一块驱动私有的原生图像存储。DPB 引用通过 V4L2
时间戳找到该存储，后处理器将结果转换为用户空间的线性 NV12。CAPTURE
的 `sizeimage` 与 payload 只描述线性图像。

H.264 Baseline profile 66 使用硬件模式 0，当前支持的 Main、High 使用
模式 15；两种模式在本驱动中均处理 8 bit 输入。build `0x1f88` 的图像尺寸
使用 8×8 CB 与 4×4 单位字段，H.264 coded 尺寸仍按完整宏块计算。

H.264 辅助表包含 920 个 CABAC 字、34 个 POC 字和缩放矩阵。模式 0 的
缩放矩阵起点为字节 3816，模式 15 为 3824。原生图像后的 MV 区域在模式 0
紧接色度数据，在模式 15 之前保留 64 字节；分配容量覆盖每组宏块的最大
需求。CABAC 常量采用有明确 GPL 许可的 Linux 表，出处见 [来源记录](sources.md)。

HEVC 的原生 stride 为 `ALIGN(4 * coded_width, 64)`，每个原生 tile 行
覆盖四个图像行。Y 与 C 之后保留同步区域，再存放每个 CTB 256 字节的 MV
数据。每次复用图像前清零 32 字节同步区。参考 POC 差在编码进 8 bit 字段
之前饱和到 `[-128,127]`，长期参考使用寄存器 38 的整字位图。

后处理器输出线性 NV12，Y 和 UV 使用同一个行距，地址分别配置在寄存器
325 至 328。寄存器 329 表示两个行距，331 和 332 表示输入与输出尺寸，
394 的两个缩放字段均为 1。参考图像压缩保持关闭。

10 bit、场解码、参考帧压缩及其他硬件 build 属于后续开发范围。
